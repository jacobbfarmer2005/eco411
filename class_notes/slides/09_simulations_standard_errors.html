Simulation

  • Simulations help us see what’s under the hood
  • We create fake data where we control the DGP
  • We know how estimators should behave
  • If our estimators break in a controlled environment, how will they perform in the wild?
  • We can repeat this random process thousands of times to separate fluke occurrences from actual problems

So how do we simulate?

  • We set up a DGP
  • Use a random number generator to create data
  • Apply the estimator we are interested in using
  • Store our estimate
  • Repeat steps 2-4 a lot of times
  • Look at the distribution of estimates

Let’s calculate the standard error for each of these

  • First, we need the sample standard deviation

\[\text{Standard Deviation} = \sigma = \sqrt{\frac{\sum{(x-\bar{x})^2}}{(n-1)}}\]

\[\text{Variance} = \sigma^2 \]

\[\text{Standard Error of the Mean} = \frac{\sigma}{\sqrt{n}}\]

Std. Dev. vs. Std. Error Intuition

  • Std. Dev. measures the variability of data within a sample
    • Does not necessarily decrease with larger n
  • Std. Error measures variability of sample means across different samples
    • Larger n gives us more confidence that we are close to the population mean
    • Will get more precise as n increases

Calculating standard deviation manually

sum_sq_dif_20 <- sum((sim_norm_20 - mean(sim_norm_20))^2)
sum_sq_dif_20_div_N <- sum_sq_dif_20/(length(sim_norm_20)-1)
#now take the square root of this object
standard_deviation_20 <- sqrt(sum_sq_dif_20_div_N)
standard_deviation_20
## [1] 1.250304

Earlier we talked about standard error of the mean

  • Is that what we are looking at when we run regressions?
    • Close, but not quite. Remember:

\[\text{Standard Deviation} = \sigma = \sqrt{\frac{\sum{(x-\bar{x})^2}}{(N-1)}}\]

\[\text{Variance} = \sigma^2 \]

\[\text{Standard Error of the Mean} = \frac{\sigma}{\sqrt{n}}\]

What about standard deviation of \(\beta_1\)

  • Same idea, slightly different execution:

\[V(\hat{\beta_1}) = \frac{\sigma^2}{SST_x}\]

where

\[\sigma = \text{variance of the error term}\]

\[SST_x = \sum (x_i-\bar{x})^2\]

As before, \(SD(\hat{\beta_1}) = \sqrt(V(\hat{\beta_1}))\)

\[SD(\hat{\beta_1}) = \sqrt(\frac{\sigma^2}{SST_x})\]

\[\equiv \frac{\sigma}{\sqrt(SST_X)}\]

  • but we don’t actually observe \(\sigma\)
  • we can estimate it using \(\hat{u}\)

Estimating \(\sigma\)

\[\hat{\sigma} = \sqrt(\frac{SSR}{(n-2)})\]

this gives us an estimate of the variance in the error term

Finally, the standard errors we see

\[SE(\hat{\beta_1}) = \frac{\hat{\sigma}}{\sqrt(SST_x)}\]

  • Which shows us that there are two ways to influence our SE’s
  • Important to remember this estimate is consistent only under the assumptions we have made

Can simulations help us understand regressions?

  • Every regression we run has assumptions baked in
  • It can be hard to know whether these assumptions hold
  • It is also hard to tell how bad it would be if they didn’t
  • What will happen if I create two fake variables with no correlation, and regress one on the other?

## [1] 79

We are clearly over-rejecting

  • The heteroscedasticity is tricking our estimator into thinking there is less variation in x than there really is
  • This makes coefficient estimates look more extreme than they really are
  • We can then be fooled into thinking a relationship is significant when it’s not
  • Fortunately, this has an easy fix

Now let’s try ROBUST standard errors

df <- data.frame(matrix(ncol=1,nrow=1000))
colnames(df) <- c("p_value")
for(i in 1:nrow(df)) {
x <- runif(1000, 0, 10)
y <- rnorm(1000, sd=x)
lm3 <- lm(y ~ x)
rob_std_errs <- coeftest(lm3, vcov = vcovHC(lm3, type = 'HC0'))
df[i,1] <- rob_std_errs[2,4]
}
sum(df$p_value<.05)
## [1] 39

So what happened here?

  • OLS key assumption -> constant variance of DV
  • Here we’ve made that assumption false
    • This breakdown causes it to look like there is less variation than there really is
    • This makes our standard errors more precise
  • Would you have noticed this issue if you were just running regressions?

We can also use simulations to test for power

  • What is statistical power
    • The likelihood of a statistical test detecting an effect when there actually is one
    • Very important for RCT’s in order to know N needed
    • (and to get funding)

Shifting gears to standard error best practices

  • We will almost always need to make some adjustment
  • Homoscedasticity assumption not really realistic
  • All kinds of other problems as well

Baseline - always start with robust SE’s

  • Heteroscedasticity makes it look like there is less variation than there really is
  • Robust standard errors address this by allowing \(\sigma\) to vary
  • Easy
    • For a better explanation, see CI: Mixtape, 2.26

What about clustering?

  • Often there will be groups in our data with common features
  • Examples: classrooms, states, firms
  • When groups have common features, they tend to have similar outcomes
    • This makes it look like there is less variation in \(u\) than there really is

Hence clustered standard errors

  • Clustered SE’s allow for correlation of \(u\) within clusters
  • This fixes this problem and gives us consistent SE’s
    • Need to have a lot of clusters
    • No set rule, but 30-50 is a good rule of thumb
    • Should be clustered at the level of treatment

So how do we do this?

state <- round(runif(1000,.5,50.5))
x <- rnorm(1000)
y <- rnorm(1000) + x + state
lm <- lm(y~x + factor(state))
summary(lm)$coef[2,1-4]
##      Estimate    Std. Error      Pr(>|t|) 
##  9.717463e-01  3.407433e-02 1.067648e-129
clust_std_errors <- coeftest(lm, vcov = vcovCL, cluster= ~state)
clust_std_errors[2,1-4]
##     Estimate   Std. Error     Pr(>|t|) 
## 9.717463e-01 4.322081e-02 4.438161e-90
